# 四栏主导航与热量日历计划

更新日期：2026-10-04

## 目标

为食衡建立长期稳定的底部主导航，让高频记录、标签扫描、历史回顾和设置不再挤在“今日”单页中。参考图只用于理解信息架构，不复制第三方 App 的视觉样式。

## 四个主页面

| 顺序 | 页面 | SF Symbol 建议 | 第一阶段职责 |
| --- | --- | --- | --- |
| 1 | 今日 | `house` | 保留当前热量圆环、营养缺口、记录一餐和今日餐食 |
| 2 | 扫描 | `viewfinder` | P2 前使用明确的功能未开放状态；P2 接入食品标签和补剂扫描 |
| 3 | 日历 | `calendar` | 月历中显示每天的总摄入热量，点选日期查看当天餐食 |
| 4 | 设置 | `gearshape` | 承接每日目标；后续加入个人约束、HealthKit、导出和隐私设置 |

## 技术结构

- 根视图使用系统 `TabView(selection:)`，选择值使用 `AppTab` 枚举，不使用整数或字符串。
- 每个 Tab 拥有独立的 `NavigationStack`，避免一个页面的导航历史影响另一个页面。
- 使用系统 `Tab`、文字标签和 SF Symbols，不手绘底栏、不硬编码底部高度，也不覆盖 Home Indicator 安全区。
- 采用系统在 iOS 26 上提供的 Tab Bar 与 Liquid Glass 行为；营养数字和规则结论仍显示在清晰实体内容区。
- 四个根页面拆为独立文件：`TodayView`、`LabelScannerView`、`NutritionCalendarView`、`SettingsView`。
- 切换 Tab 不创建或修改业务数据；SwiftData 仍是餐食和目标的唯一数据源。

## 日历页 MVP

1. 顶部显示当前年月，并支持切换上一个月和下一个月。
2. 月历按周排列；每个日期格显示日期数字和当天总热量，例如“1,860 kcal”。
3. 无记录日期保持安静的空状态，不伪造为 0 kcal。
4. 今天、选中日期和记录不完整日期使用图形或文字区别，不能只依赖颜色。
5. 点击日期后显示当天总热量、餐数和餐食列表；餐食继续复用现有详情、编辑与删除流程。
6. 编辑餐食时间、重量或删除餐食后，月历和选中日期汇总立即重算。
7. 日历数据直接由 `PersistentMealLog.eatenAt` 与营养快照聚合；MVP 不新增“每日汇总”持久化实体。

## 设置页 MVP

1. 将现有“每日目标”从今日页右上角弹窗迁入设置页的首个分区。
2. 保持热量、蛋白质、碳水、脂肪、饱和脂肪和纤维六项目标的现有保存逻辑。
3. 后续按切片增加个人医疗/饮食硬约束、HealthKit、数据导出和隐私说明；本导航切片不提前实现。

## 分阶段实施

### A. 主导航骨架

- 建立 `AppTab` 与系统 `TabView`。
- 将当前首页迁为“今日”根页面。
- 建立四个独立根页面和各自的 `NavigationStack`。
- “扫描”和“日历”在真实功能完成前使用 `ContentUnavailableView` 明确说明状态，不显示可以工作的假按钮。

### B. 设置迁移

- 将每日目标编辑移到“设置”。
- 今日页只保留目标摘要和前往设置的深层入口，减少顶部按钮和页面负担。

### C. 热量日历

- 与历史餐食查询和汇总相关工作合并实施。
- 先完成月历、每日 kcal 和按日餐食列表，再考虑周平均、连续记录或图表。

### D. 扫描页

- 与路线图 P2 同步实施，不提前安装 Vision 依赖或制作假的扫描流程。

## 验收标准

- 四个 Tab 在所有支持设备上始终位于系统安全区内，选中态清晰。
- VoiceOver 能读出“今日、扫描、日历、设置”及选中状态。
- 切换 Tab 后各页面导航状态互不干扰。
- 日历每天的 kcal 与该日所有持久化餐食营养快照之和一致。
- 修改或删除历史餐食后，今日页和日历页均自动重算。
- 未实现页面必须明确标记为未开放，不能让用户误以为按钮失效。
- 不引入第三方 UI 或日历依赖。

## 与现有路线图的关系

- 主导航骨架和设置迁移属于跨页面 UI 基础，可以在相关页面切片开始时一并完成。
- 日历 MVP 依赖已经完成的历史餐食详情、编辑、删除与重算，可作为 P0 历史能力的后续展示层。
- 扫描 Tab 只提供入口，真实功能仍严格归属 P2。
- P0 下一业务切片仍是“最近吃过”和个人常用菜模板；本计划当前只登记，不在本次改动中实现代码。
