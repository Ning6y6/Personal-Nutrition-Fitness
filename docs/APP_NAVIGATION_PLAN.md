## 目标

为食衡建立长期稳定的底部主导航，让高频记录、标签扫描、历史回顾和设置不再挤在“今日”单页中。参考图只用于理解信息架构，不复制第三方 App 的视觉样式。

## 四个主页面

| 顺序 | 页面 | SF Symbol 建议 | 第一阶段职责 |
| --- | --- | --- | --- |
| 1 | 今日 | `house` | 保留当前热量圆环、营养缺口、记录一餐和今日餐食 |
| 2 | 扫描 | `viewfinder` | P2 前使用明确的功能未开放状态；P2 接入食品标签和补剂扫描 |
| 3 | 日历 | `calendar` | 首版日期 + 记录状态标记；点选日期查看热量、完整度与当天餐食。七日趋势获批后再评估改名“趋势” |
| 4 | 设置 | `gearshape` | 承接每日目标；后续加入个人约束、HealthKit、导出和隐私设置 |

## 技术结构

- 根视图使用系统 `TabView(selection:)`，选择值使用 `AppTab` 枚举，不使用整数或字符串。
- 每个 Tab 拥有独立的 `NavigationStack`，避免一个页面的导航历史影响另一个页面。
- 使用系统 `Tab`、文字标签和 SF Symbols，不手绘底栏、不硬编码底部高度，也不覆盖 Home Indicator 安全区。
- 采用系统在 iOS 26 上提供的 Tab Bar 与 Liquid Glass 行为；营养数字和规则结论仍显示在清晰实体内容区。
- 四个根页面拆为独立文件：`TodayView`、`LabelScannerView`、`NutritionCalendarView`、`SettingsView`。
- 切换 Tab 不创建或修改业务数据；SwiftData 仍是餐食和目标的唯一数据源。
- 今日仪表盘保留自定义热量圆环与营养条；录入和设置采用系统 `Form`，不为统一外观把仪表盘强塞进表单。
- 记录入口只在今日页：对比导航栏工具栏“+”与 `.safeAreaInset(edge: .bottom)` 的系统 `.glassProminent`“记录一餐”按钮；用点击次数、误触与记录用时决定，当前 UI-1 不移动入口。
- 记录表单默认大尺寸 sheet；只有很短的快捷操作才评估 `.medium`。取消继续表达放弃草稿（`.cancel`），沿用确认对话框与下拉关闭保护；不以 `.close` 替代取消。
- 原生动效使用系统默认动画 / `numericText` 并跟随减少动态效果、减少透明度；不移植网页 480 ms 曲线。

## 日历页 MVP

1. 顶部显示当前年月，并支持切换上一个月和下一个月。
2. 月历按周排列，周起始跟随系统；每个日期格只显示日期数字与记录状态标记，不画小圆环、不使用难以阅读的微小 kcal 数字。
3. 无记录日期保持安静的空状态，不伪造为 0 kcal。
4. 今天、选中日期和记录不完整日期使用图形或文字区别，不能只依赖颜色。
5. 点击日期后显示当天总热量、日级完整度、餐数和餐食列表；餐食继续复用现有详情、编辑与删除流程。未作日确认不能仅因有餐食就标记完整日。
6. 编辑餐食时间、重量或删除餐食后，月历和选中日期汇总立即重算。
7. 日历由PersistentMealLog.eatenAt与营养快照聚合，不重复持久化每日营养总量；S3独立日级覆盖确认元数据不属于重复汇总表。

## 设置页 MVP

1. 将现有“每日预算与目标”完整编辑迁入设置页的首个分区；热量 / 碳水 / 脂肪叫预算，蛋白质 / 纤维叫目标，饱和脂肪叫上限。
2. 承接S2验收后的目标保存逻辑，不复制未加固的共享上下文保存方式。
3. 后续按切片增加个人医疗/饮食硬约束、HealthKit、数据导出和隐私说明；本导航切片不提前实现。
4. 今日工具栏可保留预算快捷入口，但完整设置迁移与快捷编辑边界须在原生外壳任务批准时明确，不重复展示两套预算信息。
5. B-1 只本地化主屏幕显示名；完整中英文界面另列任务。语言使用系统 App 语言，减少动态效果 / 透明度跟随系统，不新增与系统重复的开关。

## 分阶段实施

### A. 主导航骨架

- 建立 `AppTab` 与系统 `TabView`。
- 将当前首页迁为“今日”根页面。
- 建立四个独立根页面和各自的 `NavigationStack`。
- “扫描”和“日历”在真实功能完成前使用 `ContentUnavailableView` 明确说明状态，不显示可以工作的假按钮。

### B. 设置迁移

- 将每日目标编辑移到“设置”。
- 今日页保留简明预算 / 目标摘要和今日专属预算入口；是否直接快捷编辑或深链到设置在该切片中确认，避免工具栏与圆环重复信息。

### C. 热量日历

- 与历史餐食查询和汇总相关工作合并实施。
- S3 日确认、历史目标、日期刷新、有限查询验收后并取得日历切片批准，先完成日期 / 状态标记、选中日数值与按日餐食列表，再考虑周平均、连续记录或图表。

### C2. 七日趋势（仍待批准）

- 原排期为 S5 之后的 P5；本次 UI-1 / B-1 不提前实现。依赖满足不等于自动批准。
- 七日每日摄入使用 `BarMark`，预算参照使用该日当时生效的目标版本；缺失日期留空。不能把当前预算画成统一历史预算线。
- 使用系统图表拖选与 `numericText`；图表在上、月历在下，届时再决定是否将“日历”改名“趋势”。连续记录只奖励记录行为，不奖励低于预算或少吃。

### D. 扫描页

- 与路线图 P2 同步实施，不提前安装 Vision 依赖或制作假的扫描流程。

## 验收标准

- 四个 Tab 在所有支持设备上始终位于系统安全区内，选中态清晰。
- VoiceOver 能读出四个页面的实际标题及选中状态；若后续获批改名“趋势”，同步对应标签。
- 切换 Tab 后各页面导航状态互不干扰。
- 选中日kcal与该日正式有效餐食营养快照之和一致，D草稿排除；未知营养及估算范围独立表达。状态标记与日确认一致，不把圆环闭合作为成就。
- 修改或删除历史餐食后，今日页和日历页均自动重算。
- 未实现页面必须明确标记为未开放，不能让用户误以为按钮失效。
- 不引入第三方 UI 或日历依赖。
- 今日餐食轻量就地展开可展示食物、营养摘要与“编辑 / 复用”入口；复杂编辑仍进表单。详情保留可见编辑、删除、存模板按钮，`swipeActions` / `contextMenu` 仅作快捷操作。
