## 1. 已确认

### 1.1 英文名：Evenfare

- 中文名“食衡”不变。英文名 **Evenfare** 取代 `docs/DECISIONS.md` 005 中的英文产品名 `ShiHeng`。
- 写法：Evenfare（一个单词，首字母大写）。不要写成 EvenFare 或 Even Fare。
- 含义：even 对应“衡”（平衡、水平、平稳）；fare 对应“食”（饭食）。图标里两根平放的筷子组成“＝”，就是 even。fare 与 fair 谐音，对应超市扫描时“值不值得买”的公道判断。
- 中英组合写法：食衡 Evenfare。
- 英文副标题（已定）：Calm precision for every bowl.，见第 5 节第 5 条。
- 2026-10-07 做过简单网络搜索，没有发现同名 App，只有一家同名物流公司。没有做商标检索；如果以后公开发布，需要正式检索。

落地约束（实施前需 Ning 批准具体任务）：

- 只改主屏幕显示名：中文系统显示“食衡”，英文系统显示“Evenfare”，用 Info.plist 显示名本地化（`CFBundleDisplayName`）。
- **不要改 Bundle ID** `com.ning6y6.ShiHeng`（测试为 `com.ning6y6.ShiHengTests`）。改了系统会当成新 App，真机上已有的数据不会跟过去，也违反 `AGENTS.md` 中不得清除真机数据的要求。
- `PRODUCT_NAME = ShiHeng`（产物 `ShiHeng.app`）和内部 Target、Scheme、源码目录 `FoodDecisionAssistant` 暂时不改，沿用 005 降低重命名风险的原则。`PRODUCT_NAME` 已决定保持不改，见第 5 节第 4 条。

### 1.2 App 图标：方向 A「筷衡」（已定稿）

## 2. 网页原型审查（已排期，见第 6 节；部分条目已由第 8 节修订，以第 8 节为准）

审查对象：`tools/ui-preview`。在浏览器中看过今日、扫描、趋势（七日图和月历）、设置、记一餐展开、餐食就地展开和深色模式，控制台没有错误。

总体结论：信息结构和语义扎实，这些要保留——上下限语义分开，颜色同时配图标和文字，缺失日不当 0，连续记录不奖励少吃，玻璃不压在数字上，考虑了深色模式、减少动效和 44 pt 触控区域。不够原生的地方集中在控件和外壳。原则：能用系统控件就不自己画；系统自带的外观（玻璃、字体、圆角、间距、动画）不用网页参数去复刻。网页原型以后只用来定流程、文案和颜色，不再调玻璃、圆角和动画曲线。

| # | 原型做法 | 建议的原生做法 |
| --- | --- | --- |
| 1 | 右下角悬浮“+”按钮每个 Tab 都出现，会挡住内容 | 只在今日页提供系统记录入口；对比工具栏“+”与今日页底部系统按钮，以单手可达性和记录耗时决定。默认大尺寸记录 sheet；短操作才评估`.medium`，zoom只建立视觉关联（见第8节） |
| 2 | 自己画的底栏和滑动选中背景 | 系统 `TabView` / `Tab`；可选 `tabBarMinimizeBehavior(.onScrollDown)` |

| 4 | 自定义卡片、暖灰背景 `#F6F7F3`、可调圆角和间距 | 今日仪表盘保留圆环 / 营养条；录入与设置用系统`Form` / `Section`；背景映射系统分组色，不把全部今日页改成表单（见第8节） |
| 5 | 设置页方框复选框；App 内的减少动效、减少透明度、语言开关 | `Toggle`；减少动效和透明度跟随系统（`accessibilityReduceMotion`、`accessibilityReduceTransparency`）；语言使用系统的“App 语言”设置；“本地设计沙盒”只留在网页 |
| 6 | 480 ms 自定义动画曲线；趋势页数字逐位滚动（字距被撑开成“1 , 4 2 0”） | 系统默认弹簧动画；数字用 `.contentTransition(.numericText(value:))` |
| 7 | 取样色 `#2ED158` / `#FFD500` / `#FF4144` | 见第 3 节配色建议 |
| 8 | 记一餐：带边框输入框、网页下拉框、黄框未保存提示 | 沿用原生`Form`与草稿保护；未来食品搜索用`NavigationLink` + `.searchable`；重量带单位g。放弃草稿用`.cancel`而非`.close`，保存可用`.confirm`（DECISIONS018与第8节） |

| 10 | 七日折线 + 下方日期胶囊条 | 每日总热量用`BarMark`，预算参照使用每日历史目标，缺失日留空；用`chartXSelection`拖选，去掉重复日期条；依赖S3，不随UI-1实现 |
| 11 | 月历：灰色方块翻月按钮；每格 9 px 热量数字 | 标题旁左右箭头；首版日期 + 记录状态标记，不画小圆环。数值和完整度放选中日详情；周起始跟随系统（见第8节） |

## 3. 配色（已确认，2026-10-07）

Ning 确认采用本节方案，红色只用于硬约束。营养显示的颜色规则见第 7 节和 DECISIONS 020。

对象：网页原型默认配色（`tools/ui-preview/app.py`）。

| 问题 | 数据 / 说明 |
| --- | --- |
| 黄色进度条几乎看不见 | `#FFD500` 对浅灰轨道 `#E5EAE4` 只有 1.17:1，非文字元素应至少 3:1 |
| 绿色不能做文字 | `#2ED158` 在白底上只有 2.02:1 |
| 热量刚好达到预算就变红 | 与“温和精确”相反，也与 DECISIONS 014（预算超出不超过 10% 为琥珀）不一致。同类 App MacroFactor 被评测描述为刻意避免红色数字和“超出预算”式的责备 |
| 深色模式用了 Google 的颜色 | `#202124` 是 Google Material 深色界面的标志色；iOS 深色是纯黑背景 + `#1C1C1E` 卡片 |
| 浅色背景偏暖 | `#F6F7F3` 与系统控件的冷灰并存时会出现两种灰 |
| 绿色身兼三职 | 同时是品牌色、按钮色和“正常”状态色，状态信息被稀释 |

采用方案：

| 角色 | 浅色 | 深色 | 说明 |
| --- | --- | --- | --- |
| 背景 | `#F2F2F7` | `#000000` | 系统分组背景 |
| 卡片 | `#FFFFFF` | `#1C1C1E` | 系统分组次级背景 |
| 主题色（翡翠绿） | `#1B7F5B` | `#3DD598` | 浅色在白底上 4.96:1，可以做文字；在 Xcode 中建 AccentColor 颜色集 |
| 超出 | 系统橙 `#FF9500`，文字用 `#C93400`（5.28:1） | 系统橙 `#FF9F0A` | 替代黄色和“已达红” |
| 硬约束 | 系统红 `#FF3B30` | 系统红 `#FF453A` | 只用于清真、用药等“不符合约束”结论 |

- 正常状态不用状态色，圆环和进度条直接用主题色，只有出问题时才变色。
- 去掉黄色。
- 红色只留给硬约束，这样红色一出现就代表真的需要注意。红黄绿打分只适合扫描页的商品判断，不适合每天的摄入记录。

## 5. 原待决问题的决定

状态：已确认（授权决定，2026-10-07）。第 1 条由 Ning 本人确认；第 2–5 条由 Ning 授权 Claude 按当前阶段和后续规划决定。

2. **UI 建议的排期**：见第 6 节。
3. **图标定稿**：采用方向 A 的现有几何和颜色（第 1.2 节）。图标浅色背景 `#1E8F64` 比 App 主题色 `#1B7F5B` 略亮，在主屏幕上更醒目，两者同属翡翠色系，这是有意的。真机验收：在主屏幕（60 pt）、设置列表和 Spotlight（29 pt）查看，两根筷子必须仍能分开。如果 29 pt 下糊成一条，只改两处：筷子高度 48 → 56，两根之间的空隙 24 → 28（第二根筷子 `y` 相应改为 386），其余不变。

## 7. 热量环 v2 与营养显示颜色

状态：已确认（2026-10-07）。Ning 提出“超出部分叠在第一圈上并变琥珀色”以及“吃到 3 倍怎么表现”，下面是采用的方案。画面效果见 Claude 设计画布“热量环 v2”。

- **预算内（0–100%）**：一圈主题色，同色系角度渐变，起点深、末端浅（浅色 `#1B7F5B` → `#2FB47C`，深色 `#2BB57E` → `#3DD598`），像 Apple 健身的活动圆环。
- **不采用“浅绿 → 琥珀”的位置渐变**：那样吃到 70–90% 时环的末端已经发黄，在预算内就暗示“快不行了”，违背 DECISIONS 014“预算未满不催促”的语义。
- **超出（> 100%）**：第一圈保持主题色并闭合；超出部分从 12 点方向开始，用琥珀色叠在第一圈上，同样是同色系渐变（浅色 `#E07B00` → `#FF9500`，深色 `#E8890A` → `#FF9F0A`）。末端圆帽加轻微阴影，让重叠的边界看得出来。
- **最多两圈**：超出部分最多画满一圈，也就是摄入达到预算 2 倍时琥珀圈闭合；再多，图形不再变化。倍数和差额用文字表达，例如“超出 4,400 kcal · 约为预算的 3.2 倍”。不用红色，也不把颜色加深。
- **文字与图标**：颜色从不单独表达状态。预算内写“预算剩余 X kcal”；刚好达到写“已达预算，尚未超出”；超出写“超出 X kcal”，达到 2 倍及以上时追加“约为预算的 N 倍”。
- **色弱**：深色模式下翡翠和琥珀亮度接近，红绿色弱的人可能分不清，所以要靠末端阴影和状态文字来区分。
- **异常值确认（UI-BEH-01，单独行为任务，未批准实施）**：单餐热量超过当日预算的1.5倍，或单分项超过2,000g时保存前核对输入。此处仅记录后续方案，不随UI-1改保存流程。未来需Core可测试函数、确认 / 返回修改 / 取消零写入与保存失败验收。
- **其他营养素**：预算型（碳水、脂肪）超出一律用琥珀。上限型（饱和脂肪）达到 80% 起用琥珀预警，超过 100% 仍是琥珀，并写明“超出上限 X g”。下限型（蛋白质、纤维）的进度条始终用主题色，达标后加对勾。
- **Core 改动**：`EnergyProgressSummary` 增加 `baseLap = min(ratio, 1)`、`overflowLap = min(max(ratio − 1, 0), 1)` 和 `multiple = ratio`。`NutritionDisplayPolicy` 升为 v2，营养显示里不再映射红色；v1 保留，用于兼容旧数据解码和旧测试。
- **SwiftUI 实现提示**：用 `Circle().trim` + `AngularGradient` + `StrokeStyle(lineCap: .round)`。整圈渐变在 12 点处会有接缝，按常见做法把末端圆帽和阴影单独画出来。
