## 实际改动与边界

App层集中日期展示上下文。当前界面语言为简体中文，日期文本及两个原生日期选择器共用展示规则；保留手机地区、12／24小时偏好、当地时区和既有餐食日历偏好。前台、locale或时区更新时刷新上下文，不重建页面身份或重设草稿基线。

今日副标题显示完整日期，今日餐食摘要显示时间，历史餐食显示日期和分钟、跨年补年份；餐食详情显示完整日期和分钟。目标列表的确认时间保留分钟，版本详情保留秒。无效旧时间显示不可用，不生成替代日期。

目标生效日期仍从Gregorian民用`GoalDay.key`显示，同年省年份，跨年或无参考日保留年份；不从`effectiveFrom`或新时区重新推导。确认时间、餐食时间是时间点，按当地时区展示；原确认时区和保存快照不改，未知过去目标仍未知。目标选版继续按原当地统计日规则执行。

展示语言参数为未来界面语言预留；本片没有完整英文界面或语言开关。只对日期文本及日期选择器应用展示locale，不替换全局数字locale，不改变数字输入、小数解析、保存命令或既有表单时区保护。展示变化本身不作废匹配的重试请求；实际时区或小数分隔符变化仍按原逻辑作废。英语显示名、Bundle ID `com.ning6y6.ShiHeng`、Core、SwiftData V1/V2、迁移、备份、本地唯一约束和现有保存命令保持，无新增依赖。

## 失败证据与修正

首次App单元测试构建因工程中新测试文件路径漏掉`App/`目录而失败，修正引用后全量R2通过。该问题属于工程路径错误，不归为环境权限失败。

英国UI R1在核对100g食品快照时失败：真实英文环境的可访问性组合使用英文逗号连接，旧测试只接受中文顿号。根据实际层级精确增加同一食品名称和100g的英文连接形式，保留前台详情范围及精确重量，不采用含糊包含匹配。

英国UI R2在历史餐食中遇到与底层今日页同一餐食UUID的详情动作重复。测试改为限定前台容器，仍要求唯一匹配；未改生产动作、保存或数据。这项定位修正本身不算通过，上述失败原始证据保留。

英国UI R3在目标紧凑日期按钮处失败：原生AX名称是通用`Date Picker`，真实value为中文日期。临时只读picker-inspectR1确认了名称和值的差别，测试随后读取真实显示值，不放宽中文日期断言。

picker-inspectR2又发现原生日历日期按钮的AX名称跟随进程英文，例如`Friday 16 October`；截图中的月份和星期可见文本为中文。测试对同一个预期民用日独立生成精确的英国／美国AX候选，仍要求唯一按钮，中文月份和选中后的生效摘要保持严格核对。picker-inspectR3真实选日及取消／继续／放弃1项通过，临时日历、Settings观察和逐条清理测试均在交付前移除，保留永久的两地区和AX回归用例。原生日历的动作名、日期名及滚轮单位描述与可见中文不是同一种语言来源；本轮截图证明可见中文，VoiceOver实际语言体验仍待验收。

两地区final-R1均在旧来源说明的原生Cut步骤失败，实际元数据证明剪切后仍有文字，未建立全选。该失败属于具体测试输入操作，不归为App或环境故障。改为通过真实键盘追加本轮唯一标记识别新版本，保留原版本和精确日期、时间、重量及唯一性断言。final-R2两地区完整串行流程2／2通过，旧失败保留且未计为通过。

AX R1、R2将滚轮当作紧凑年月日文本而失败；R2实际树显示三个滚轮：今天、小时、分钟，没有完整年份。改按真实滚轮结构核验后，英文英国地区R3又因假定AX单位必须是“点／分钟”失败：截图显示中文日期与纯数字，实际AX描述为`o’clock/minutes`。R4保留唯一日期控件、三滚轮、中文“今天”、小时0…23、分钟0…59及输入／取消保护，允许已观察的精确单位后通过。没有改生产控件、注入日期或把英文AX描述当成中文；它们的VoiceOver体验仍未测。

系统Settings初始3次只读检查后，另用1项辅助UI用例滚动General和Language & Region到底，仍未找到系统时间制开关。没有改偏好，没有通过私有偏好写入、假状态栏时间或地区默认冒称已完成系统切换。环境能力限制与UI断言、工程路径失败分别记录。

## 真机验收流程

先记下原语言、地区、24小时制、时区及字号，私下导出全量备份。保持同一Bundle ID原地更新，不卸载、不清库。只核对本人已有真实餐食和目标，不存假餐、不新增测试目标、不删除记录。

1. 手机设为英文、英国地区，打开App。检查今日副标题、已有真实餐食摘要／详情／历史日期使用中文，餐食重量、时间点和营养快照保持。打开“记录一餐→空白记录”，只查看原生日期控件，然后取消，不保存。
2. 手机改为英文、美国地区，重复日期文本和两个日期控件检查。查看目标历史及详情：生效日期保持原民用日期，确认时间为中文、详情仍有秒；查看未知历史说明，不把未知过去当成当前预算。
3. 实际切换系统12小时／24小时制，再返回App，检查餐食、确认时间和记餐日期控件一致，12小时使用中文时段，24小时没有时段。可在有未保存输入的表单中切换后返回，核对输入仍保留，取消时可继续或放弃；不为验收保存新餐或目标。
4. 记下已有餐食及目标确认时间、目标生效日期和原确认时区。实际切换手机时区，经前后台返回后，时间点应按新当地时区显示，目标生效民用日期和原确认时区不变；若当地日期不同，当前目标按原选版规则变化，不代表历史被改写。
5. 目标表单打开时切换时区，返回后核对所选民用日期和数字草稿未被静默重填或推进。日期控件跟随表单当前时区；既有刷新逻辑保持所选民用日期、更新表单时区并作废旧重试请求，不自动保存；只取消、继续编辑或放弃。最大辅助字号下核对日期控件可达，结束恢复原字号。
6. 恢复原语言、地区、24小时制、时区和字号，再核对原餐、目标历史和数字输入。逐项记录通过、失败或未测；私下保存必要截图、机型与iOS版本，个人数据不进Git。VoiceOver和真实午夜切换未做时保持未测，不能用其他步骤替代。
