## 变更

- 餐食“食物分项”和模板“默认分项”的标题右侧共用轻量“编辑／完成”文字按钮，保留原标题、行内容、重量、来源和添加入口。
- 进入编辑模式先收起软件键盘，显示系统原生分项删除控件；使用既有`onDelete`删除草稿行，常态左滑删除继续可用。
- 点击完成只收起删除控件；点击食品进入搜索前退出删除模式，搜索与资料页保留原交互。
- 模式切换不改变草稿或建立新基线。真正移除分项仍受原保存／取消／继续编辑／放弃守卫保护；剩余分项必须完整才能保存，全部删除后禁用保存，仍可完成或重新添加。
- 标题按钮提供44pt最小命中区，字号跟随系统；新增空间限于分项标题，不增加分项内常驻图标或额外行。

没有修改Core规则、营养计算、食品目录、SwiftData V1／V2、迁移链、备份格式、唯一约束或Bundle ID `com.ning6y6.ShiHeng`；没有依赖或网络服务变更。没有操作真机、私人数据库或健康备份，没有卸载清库。原工作区九项未提交文档独立保留，不纳入本片提交。

## 真机验收步骤

沿用现有App覆盖安装，不卸载、不清库。先使用未保存草稿检验，正常保存时使用当次真实饮食；不要为验收删除未知或真实历史记录。

1. 今日→记录一餐→空白记录。在“食物分项”右侧看到小的“编辑”；默认没有常驻红色减号，食物／重量／来源布局保持原样。
2. 仅点击“编辑→完成”，再点顶部取消：没有改动的表单应直接返回，不出现放弃修改提示。
3. 重新打开，为真实餐选食物并填重量；再添加一个完全空白分项。保存此时不可用。点标题编辑，在最后空白分项使用系统减号及删除动作；只移除该项，前面食品、重量原文（例如100.0）、标题和时间保留，保存恢复可用；此时先核对原文，再提交保存。
4. 点击标题完成，确认减号收起；正常保存并打开详情，食品、重量和营养正确，没有额外空分项。
5. 在未保存草稿验证当前左滑删除仍可用；删到没有分项时保存禁用，完成仍可点击，添加食物后可以继续填写。明确放弃该测试草稿。
6. 打开一个已有餐食编辑，移除一项后点顶部取消→继续编辑，移除后的草稿应保留；再取消→放弃修改，回到详情核对原已保存餐食仍未改变。选择适合检查的记录，不按保存提交本次试删。
7. 记录一餐→管理常用模板→新建或编辑模板，重复“添加空白行→编辑→仅删该行→完成”。模板也需核对：仅切换编辑→完成后取消，不出现放弃提示；删光后保存禁用但完成仍可点击；有效模板可以保存，食品与默认重量原文保持。对已有模板试删后放弃，重开仍是原内容。
8. 键盘打开时点分项编辑，应收起键盘并可操作删除；在删除模式开启时从食品行进入搜索再返回，当前食品选择和重量原文不丢，标题应恢复“编辑”、减号收起；搜索页没有分项删除控件。不要求跨次进入保留搜索词。
9. 浅／深色与较大文字各检查一次，标题编辑／完成及删除动作可见可达。真机VoiceOver操作若未做，继续单列待验。

若任一步出现删错行、其他重量变化、未保存就影响原记录或保存失败丢草稿，本片不通过，保留现场后反馈具体步骤。
