## 实施边界

1. 仅全新、未带来源的餐食／模板编辑器启用空占位栏例外。删除前必须仍完全等于最初草稿，且只有一个食品引用为nil、名称为nil、重量原文为空的分项；删除后其他字段必须完全不变、分项为零。
2. 该例外只供取消与下拉关闭使用，未重置最初基线。严格差异检查和加载保护仍认为实际结构变化存在；保存校验、失败重试、保存命令与数据库逻辑不变。
3. 已保存／复用／模板带入内容不启用例外；改名称、时间、方式、完整度，食品引用／名称、非空或非法重量原文均继续保护。后续再次删除会撤销原例外，防止新增并编辑的内容被一并忽略。仅删空白占位栏不会生成餐食或模板，零分项仍不能保存。
4. 餐食删除确认绑定到实际“删除餐食”按钮；模板确认绑定到对应稳定列表行，避免左滑动作收起后源控件消失。模板呈现、取消、确认均核对待删UUID，只允许对应一行处理当前操作。
5. 继续使用系统原生确认及自适应布局。空间不足可以向上展开，箭头／来源应与触发控件对应；不承诺固定坐标，也不新增常驻按钮或重排表单。保留原删除后的重算和失败回滚。

SwiftUI、Swift 6、SwiftData、FoodDecisionCore、357项食品目录与Bundle ID `com.ning6y6.ShiHeng`保持。无Schema、迁移链、备份格式、唯一约束、依赖或网络服务变更。原主工作区九项未提交改动独立保留，不混入本片。

## 真机验收步骤

覆盖安装本片新版，不卸载、不清库。除当次真实饮食正常记录外，其余检查使用未保存草稿或明确测试样本，不删除未知历史记录。

1. 今日→记录一餐→空白记录。不改名称、时间，不选择食物、不填重量；点“食物分项→编辑”，删除唯一初始空白分项，再点顶部取消。应直接退出，不出现“放弃修改／继续编辑”，今日餐数与已记录营养不变。重开应仍有一条新的空白输入栏。
2. 重新打开空白记录，重复删除唯一初始空白栏后下拉关闭。应能直接关闭；只切换“编辑→完成”再取消也不提示。零分项时保存必须不可用。
3. 再开空白记录，先改餐食名称（或时间），再删初始空白项并取消。此时必须仍提示：点继续编辑，名称／时间及零分项草稿保留；再取消→放弃修改，返回且没有新增餐食。
4. 在未保存草稿填入食品或重量（可检查 `.` 等无效原文），删除该有输入分项后取消，仍应提示。已有餐食编辑／模板带入／最近吃过的内容试删后放弃，重开必须保留原已保存记录；不要按保存提交试删。
5. 记录一餐→管理常用模板→新建，重复第1–4项适用步骤。纯空占位栏可直接取消；改模板名称、输入或编辑已有模板后，继续保留放弃保护；操作不应新建模板。
6. 打开已保存餐食详情，滚动到底部“删除餐食”并点击。确认文字必须是当前餐食名称，浮层来源靠近该按钮、箭头对应它；可向上展开，但不能像旧图那样远离触发处。在系统取消或浮层外部取消后，原餐食及今日合计保持。
7. 管理常用模板→选一条明确的测试模板→左滑删除。确认名称与该行一致，浮层靠近该行；先取消，再对另一条明确测试模板打开确认，不能显示上一条名称或删错项。只在自建测试样本上最终确认删除，验证仅该模板消失，历史餐食保持。
8. 浅／深色和较大字号各检查一次，特别是滚动后触发的两个确认框。长名称可以换行，确认动作应可见可点；系统可根据空间改变展开方向。实际VoiceOver与真机结果由用户单独确认。

若出现有输入却直接丢弃、取消仍删除、确认名称串行、错误删除或保存失败丢草稿，本片不通过。保留复现步骤，不用卸载／清库绕过。
