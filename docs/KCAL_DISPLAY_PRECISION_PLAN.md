## 范围与规则

- 在App层集中kcal展示。今日热量环／预算／剩余／超出、餐食摘要与展开、历史／详情、记餐及编辑／复用预览、最近吃过、空态已保存预算和目标历史／详情使用同一函数。
- 非负有限值≥1按四舍五入（恰好半数向远离零）显示整数，保留手机地区的数字分组；真实0显示0；0到1之间的正值写“不足 1 kcal”，避免少量摄入、预算或差额伪装成0。
- Core继续按原始Double判断状态、差额、圆环与倍数。状态不由显示整数决定：例如2000.01超出2000，仍显示“超出预算不足1kcal”，不能变成达标。倍数不是kcal，保留原精度。
- 各值独立显示取整；今日合计先按原精度求和再显示，不对单餐先取整再求和。因此显示的单餐整数相加可能与合计相差1kcal。没有新统计规则。
- 缺失、未设置和异常保持各自语义；非法kcal写不可用，不显示0。无记录仍为已有中性占位，不代表实际摄入为零。
- 克数与纤维未知／已知小计格式、日期语言、页面布局、导航和操作保持。目标输入和重量输入继续保留原始文本及Double往返精度，不把展示字符串写回草稿或数据。

不改Core、SwiftData实体／V1／V2／迁移、唯一约束、备份、保存命令或Bundle ID `com.ning6y6.ShiHeng`，无新依赖。原工作区9份未提交内容按状态／差异／哈希保留，未纳入本片。
