# kcal 显示精度统一报告

批准日期：2026-10-16。基线：`56860ec`。分支：`fix/kcal-display-precision`。本片范围见[实施计划](KCAL_DISPLAY_PRECISION_PLAN.md)。用户已反馈上一片中文日期时间验收通过，该项按用户反馈记录。

## 改动与边界

App 层新增共享 `KcalDisplay`，统一今日环的摄入、预算、剩余与超额，以及餐食摘要／展开、详情、记录／编辑／复用预览、最近吃过、空态已保存预算、目标历史和详情。

- 大于等于 1 kcal 的有限非负数显示整数；恰好半数向上，例如 235.8 → 236、236.5 → 237。数字分组继续跟随地区。
- 真正零显示 0；0 到 1 之间的正值显示“不足 1 kcal”。缺失／未设置保持原语义；非法值显示“不可用”。
- Core 用原始 Double 计算状态、差额、进度和预算倍数。2000.01 对 2000 即使两边都显示 2000，仍提示“超出预算 不足 1 kcal”并保留警示。
- 合计按原始值先求和再显示。例如两份 98.25，各显示 98，合计 196.5 显示 197；显示整数相加可能相差 1 kcal。
- 目标输入仍能显示并保存原来的 2000.25；重量草稿和保存快照保留原精度。克数、纤维、预算倍数、日期、布局和操作不变。

未改 FoodDecisionCore、SwiftData V1／V2／迁移、唯一约束、保存命令、备份格式或 Bundle ID `com.ning6y6.ShiHeng`，未增加依赖。原工作区 9 项未提交内容单独保留，不混入本片。

## 真机验收方式

在同一 Bundle ID 原地更新，不卸载、不清库。检查本人已有真实数据；需要保存个人截图或备份时放在 Git 之外。无需为验收新增假餐或目标。

1. 找一条原有带小数热量的餐食，对照更新前数值：例如原值 235.8 kcal 应显示 236。依次核对今日摘要（若属于今日）、展开、详情、历史及“最近吃过”。这些页面应一致；日期、重量和克数保持。
2. 打开该餐的编辑页，核对原重量与营养预览；不改动直接取消。复用仅打开草稿核对，随后取消，不能多出一条记录。若试改重量，取消时选择放弃，返回确认原餐未变。
3. 今日有真实记录时，查看摄入、预算、剩余或超额均为整数。先用原始值合计再取整；不要要求屏幕上各餐整数直接相加必然等于合计。若原始正差额不足 1，应显示“不足 1”，不能显示“超出 0”或变成达到预算。
4. 查看已保存目标及目标历史详情：预算显示整数。打开目标编辑页只查看输入，原有小数仍保留；取消，不为本次验收保存目标。未知历史仍未知，未来生效安排和确认时间不变。
5. 在常用浅色／深色及大字号下核对 kcal 文案可读、原有操作可达。逐项记下通过／失败／未测；没有现成极小正值或边界记录时记为未测，自动化证据单独列出。VoiceOver、真实午夜和时区切换未执行时保持未测。
