# “记录一餐”首版落实计划

状态：已完成
开始日期：2026-10-04
完成日期：2026-10-04

## 1. 本次目标

完成一个可以每天真实使用的本地记录闭环：从首页进入“记录一餐”，添加一个或多个食物分项，输入称重或估算份量，由本地食物库计算营养，保存到 SwiftData，并在今日页看到当日合计和最近记录。

## 2. 范围边界

本次包含：

- 称重/包装数据记录，证据等级自动记为 A。
- 标准份量或经验估算，证据等级自动记为 B。
- 一餐包含多个有明确顺序的食物分项。
- 分项重量、本地计算结果和食物名称快照持久化。
- 记录覆盖状态独立选择为完整、部分或临时。
- 首批个人常用食材种子库，营养来源可追溯。
- 今日摄入合计、目标进度和最近餐食展示。

本次不包含：

- 相机、照片选择、真实 AI 或图片上传。
- 食品标签 OCR、商品判断和待核对流程。
- 菜谱批次、剩菜复用、容器皮重和自定义食物编辑。
- HealthKit、CloudKit 或营养数据导出。

## 3. 执行阶段与完成条件

- [x] 阶段一：领域模型与计算
  - 新增餐食分项和记录方式模型。
  - 校验重量必须大于零、餐食至少有一个分项。
  - 按每 100 克营养计算分项快照并汇总整餐。
  - FoodDecisionCore 单元测试覆盖缩放、汇总、校验和 Codable 往返。

- [x] 阶段二：SwiftData 持久化
  - 新增 `PersistentMealComponent`，与 `PersistentMealLog` 建立级联关系。

  - 更新 `VersionedSchemaV1.models` 与持久化测试。

- [x] 阶段三：个人种子食物库
  - 导入米饭、西红柿、鸡蛋、青椒、茄子、豆腐、牛肉、鸡肉、食用油和酱油等常用条目。
  - 使用固定 UUID 和幂等导入，重复启动不产生重复数据。
  - 每条数据保留 CoFID 代码和版本；缺失营养不伪造为精确值。

- [x] 阶段四：记录一餐界面

  - 无有效分项时禁止保存并给出明确提示。

- [x] 阶段五：今日页反馈

  - 显示最近餐食、时间、能量和证据等级。
  - 保存成功后关闭录入页并立即刷新今日页。

## 5. 验收场景

1. 新安装后种子食物自动出现且重启不重复。
2. 记录“西红柿炒鸡蛋”：西红柿、鸡蛋、食用油三个分项均可输入重量，营养实时汇总。
3. 称重记录保存为证据 A；标准份量估算保存为证据 B。
4. 保存后今日页立刻出现该餐，并计入当日合计。
5. 分项为零克、没有分项或标题为空时不能保存。
6. 历史餐食保存的是营养快照，未来种子库更新不会静默改写历史记录。
