# 最近吃过与个人常用菜模板开发计划

更新日期：2026-10-04

## 目标

完成路线图 P0 的第二部分，降低重复录入成本。用户从“最近吃过”或“个人常用菜模板”生成一份新的餐食草稿，只需修正本次重量即可保存，目标是将常用餐重复录入控制在 30 秒内。

## 严格范围

本切片只实现：

1. 从历史餐食计算最多 6 条不重复的“最近吃过”。
2. 建立个人常用菜模板及分项的领域模型和 SwiftData 持久化。
3. 使用统一 `MealEntryDraft` 将历史餐食、模板或空白输入送入现有录入表单。
4. 从餐食详情将现有餐食保存为模板。
5. 新建、重命名、编辑默认重量和删除模板。
6. 从最近餐食或模板复用时默认为标准份量估算，即证据 B；用户重新称重后可手动改为证据 A。
7. 实际保存餐食后才更新模板的最近使用时间和使用次数。

本切片不实现：Supabase、CloudKit、模板分享、模板文件夹、AI 拍照、标签扫描、HealthKit、自定义食物、外卖份量单位或四栏主导航代码。

## 数据边界

- “最近吃过”不建立持久化实体，由最近 30 条有效历史餐食实时计算。
- 去重键为规范化餐食名称与食物 ID 组成；相同组合保留时间最新的一条。
- 模板保存食物 ID、显示名称、默认克重和顺序，不保存最终营养值。
- 每次使用模板时由当前本地 `FoodItem` 重新计算营养；保存餐食后写入新的营养快照。
- 删除模板必须级联删除模板分项，但不得影响任何历史餐食。
- 模板引用的食物已不存在时必须阻止保存并要求重新选择，不能静默丢弃分项。

## 实施顺序

### 1. 领域规则与测试

- 增加 `MealTemplate`、`MealTemplateComponent`、`MealEntryDraft` 和草稿分项。
- 增加最近餐食的排序、去重和数量限制规则。
- 测试复用时生成新分项 ID、证据 B、模板来源追踪和异常输入。

### 2. SwiftData 与测试

- 增加 `PersistentMealTemplate` 和 `PersistentMealTemplateComponent`，采用明确 inverse 与级联删除。
- 增加领域双向转换、模板更新、使用计数和旧分项清理。
- 项目尚未发布，继续补入 `VersionedSchemaV1`，不创建开发期专用 V2。

### 3. 快速复用界面

- “记录一餐”先打开快速开始页，展示最近吃过、常用模板和空白记录。
- 选择历史或模板后进入现有餐食表单，允许修正名称、时间、分项和重量。
- 没有历史和模板时仍可直接进入空白记录，不展示失效操作。

### 4. 模板管理

- 餐食详情提供“保存为常用模板”。
- 快速开始页提供模板管理入口。
- 模板管理支持新建、编辑和带确认的删除。

## 验收标准

- 最近餐食按时间倒序、正确去重且最多 6 条。
- 相同名称但食物组成不同的餐食不会被错误合并。
- 复用草稿的分项 ID 与原记录或模板不同。
- 历史和模板复用默认显示证据 B。
- 模板保存、更新、读取和分项顺序往返正确。
- 删除模板会清理模板分项，但不删除历史餐食。
- 使用模板保存成功后 `lastUsedAt` 和 `useCount` 才更新；取消不更新。
- 食物引用失效时不能保存。
- `FoodDecisionCore`、iOS SwiftData 测试和 App 构建全部通过。
- 真机上选择模板、修改重量并保存的主路径不超过 30 秒。
