## UI-2A：系统四栏与设置迁移

状态：代码与适用功能门禁已通过；键盘布局诊断、真机专项和 iOS 26 运行时仍明确挂账，不把构建或截图当作交互验收。

### 实现

- `AppTab`、`ContentView`：系统四栏，独立 `NavigationStack`，根级种子导入保留幂等。
- `TodayView`：移动原今日仪表盘，不改营养计算、空态、历史或保存流程；返回今日时重读目标，刷新日期并恢复前台午夜任务。
- `SettingsView`：原生 `Form` 承接既有目标和本地备份界面；不复制目标保存或备份实现。
- `LabelScannerView` / `NutritionCalendarView`：明确未开放，没有假数据或失效业务按钮。
- `NativeShellPreviews` / `NativeNavigationTests`：四栏浅深色、最大辅助字体及零业务写入的整页原生渲染。
- 标准 `FoodDecisionAssistantUITests` target 与共享 Scheme：用 XCTest 操作系统 Tab 和既有表单。未添加第三方依赖或 App 专用测试启动模式。

### 键盘布局警告的边界

R2 / R3 的两条警告都落在目标表单首次点击输入框、键盘弹出的瞬间，在 `typeText` 前；R3 activity 标记 `isAssociatedWithFailure=false`。此时今日为中性空态，没有渲染热量环；目标表单无 `.frame` / `GeometryReader`。xcresult 调用栈没有符号或源码位置，不能据此断言是系统 bug，也不能随意修改营养数值或添加 frame 钳位。

后续 UI-2B 原生大尺寸 sheet / 键盘工具栏验收需要再次观察，并可将同目标表单在有 / 无 Tab 外壳下做隔离比较。运行时警告单独挂账，自动化成功不等于零警告、VoiceOver 或真机键盘体验已经通过。
