# 原生 UI 整改执行计划

更新日期：2026-10-08。状态：UI-2A代码及适用功能门禁已通过；UI-2B已批准、作为下一片，UI-2C等待UI-2B门禁。后两片尚未实施。

## 本轮批准与执行顺序

本轮批准的是既有页面的原生 UI 整改，不是只加底栏，也不是开放全部 S3。UI-1 配色 / 用词 / 热量环 v2、B-1 显示名与图标工程接入已有独立交付证据；现在按 **UI-2A → UI-2B → UI-2C** 顺序实施。每一片独立验证、提交，相关保护与模拟器交互通过后才进入下一片，不同时开工。

整改按适用门禁推进，不承诺未经评估的完工日期，也不等待 AI、HealthKit 或全部 S3 / S4 / S5 完成。尚未实测的 VoiceOver、iOS 26 运行时、真机跨午夜 / 时区等继续挂账；这些未测项不构成不改数据库的 UI 切片统一阻塞条件，也不能被新批准改写成已通过。

本轮遵循 [品牌决定第 8 节](BRAND_UI_DECISIONS.md)、[导航计划](APP_NAVIGATION_PLAN.md) 和 [可靠性执行清单](OPTIMIZATION_EXECUTION_PLAN.md)。网页原型只提供流程参考，不复制其 CSS 玻璃、480 ms 曲线、逐位计数器或同一 DOM 容器形变。

## 共用边界

- 使用 SwiftUI 系统控件、SF Symbols、默认动画及已建立的语义设计系统；玻璃只用于浮层交互，数字和营养结论保持清晰实体表面。
- 保留 Bundle ID `com.ning6y6.ShiHeng`、内部产物 / Target / Scheme、冻结 12 实体 V1、唯一约束、数据库路径与全部保存 / 恢复事务。
- 保留营养快照、minimum / budget / maximum、未知值与已知 0、正式记录与草稿 / 异常记录的区分；不增加医疗阈值或整日完整判定。
- 不添加第三方依赖、账号、云同步、真实 API、照片上传、HealthKit 或新存储实体。
- 已有详情、编辑、删除、复用、存模板及备份恢复入口必须仍可到达；不会为了整理页面隐藏旧记录或删除数据。
- 食品搜索属于 OPT-12，日确认 / 目标历史 / 有限查询属于 S3 相应任务，个人食物卡与菜谱批次属于 S4 / S5；本轮未新增这些业务批准。
- UI-BEH-01 异常输入保存确认、完整中英文界面、真实扫描、完整日历及趋势仍未批准实施。原生表单整理不改变已有保存确认、校验或默认记录方式。

## UI-2A：系统四栏与设置迁移

分支：`feat/native-tab-shell`。状态：已实施，适用原生预览、模拟器实际交互、全量回归及最终构建通过。

### 实施内容

1. 建立 `AppTab` 与系统 `TabView` / `Tab`，四栏为“今日、扫描、日历、设置”，每栏使用独立 `NavigationStack`。
2. 将已有今日仪表盘迁为独立根页面；保留热量环、营养条、今日记录、全部历史入口、日期刷新及空态语义。
3. 扫描与日历使用 `ContentUnavailableView` 明确说明尚未开放；不显示假的相机、日历数据、扫描结论或失效业务按钮。
4. 设置使用原生 `Form` 承接既有“每日预算与目标”编辑入口，复用同一编辑 / 保存命令，不复制第二套表单状态或目标持久化逻辑。
5. 今日专属预算快捷入口继续可达并复用同一目标编辑流程；工具栏固定在滚动内容之外，不在所有 Tab 显示预算控件，不重复堆叠预算信息。
6. 保持已有备份 / 恢复能力和入口可达，可从今日迁入设置并复用现有流程；不要求两个位置重复入口，不开发另一套导出 / 恢复，也不删除既有能力。

### 完成门禁

- 四栏安全区、标题 / 选中态、独立导航状态、浅深色和最大辅助字体原生预览及模拟器检查通过。
- 切换 Tab 不写入业务数据；返回今日不重建正在编辑的表单或丢失已有日期刷新语义。
- 目标确认 / 留空 / 明确 0 / 取消 / 保存失败与草稿保护回归通过；成功编辑后今日读取最新已提交目标。
- 旧餐食 / 模板 / 历史 / 备份入口仍可达，冻结 Schema / 身份回归保持通过。
- 当前 Core / 全量 App 测试与 iOS 构建通过，记录实际数量及未实测项；通过后才开始 UI-2B。

## UI-2B：今日记录入口与原生表单

建议分支：`feat/native-meal-entry-ui`。状态：已批准、尚未实施；UI-2A适用门禁已满足，按独立分支作为下一片。

### 实施内容

1. 只在今日页比较工具栏“+”与 `.safeAreaInset(edge: .bottom)` 中系统 `.glassProminent`“记录一餐”按钮；不使用所有 Tab 共用的 Material FAB，不遮挡餐食与 Tab Bar。
2. 用原生预览和模拟器比较单手可达性、点击步骤与误触；真实用户耗时未取得时明确标注，不能用代理自动点击宣称完成 30 秒真机业务验收。
3. 记录表单默认大尺寸 sheet，复用既有最近 / 模板 / 空白记录和餐食草稿流程。可评估系统 zoom 建立入口关联，但不实现网页同容器形变或指定 480 ms 动画。
4. 对记录、目标、模板既有表单统一 `Form` / `Section`、可见输入标签、单位、键盘完成与错误层级；高级信息渐进展开，长说明收进 footer 或信息入口。
5. 保持 `.cancel`、`confirmationDialog`、`interactiveDismissDisabled`、原始非法输入保护、保存失败保留输入与读取重试保护；不以 `.close` 替代放弃草稿。
6. 系统动态字体、减少动态效果与减少透明度参与布局 / 材质降级，不增加重复的 App 内辅助功能开关；不顺带开发食品搜索或完整语言设置。

### 完成门禁

- 键盘打开 / 关闭、中文输入、数字非法中间态、最大辅助字体与浅深色下主要操作均可达，没有字段标签缺失或底部遮挡。
- 餐食、目标和模板三个表单的未修改退出、修改后下拉、继续编辑、放弃、合法保存、失败保留及读取重试回归通过。
- 重复触发记录入口不创建重叠表单、不重复写餐；保存成功仍沿用既有事务和今日汇总刷新。
- 原生页面预览、相关模拟器实际交互、Core / 全量 App 测试与构建通过；记录 A/B 选择依据与仍待真机验收项，通过后才开始 UI-2C。

## UI-2C：餐食轻量就地展开

建议分支：`feat/inline-meal-details`。状态：已批准，等待 UI-2B 适用门禁。

### 实施内容

1. 今日 / 历史餐食行共享视觉规则和轻量展开组件；展开状态按餐食 ID 保存在瞬时界面状态，不新增持久化字段。每个列表同时只展开一项。
2. 就地显示现有食物分项、营养快照摘要与“编辑 / 复用 / 查看详情”入口；不加占位插画、重复标题或新营养推断，复杂编辑继续进入现有表单。
3. 详情保留可见的编辑、删除和存为模板操作；`swipeActions` / `contextMenu` 只能是快捷方式，不能成为唯一入口。
4. 使用真实内容布局及系统动画，展开 / 收起尊重减少动态效果；不固定行高、强制三段延迟、复制网页曲线或制作新弹层。
5. 编辑日期、删除或列表数据变化时清理失效展开状态；既有详情与历史中的 D / 异常记录可见性、警告和操作边界保持不变。

### 完成门禁

- 展开 / 收起 / 快速切换项目、长中文名、长食物列表、未知纤维、草稿 / 异常提示及浅深色 / 最大字体预览和模拟器检查通过。
- 展开本身零业务写入，显示值来自原餐食快照；不从当前食物库悄悄重算历史营养。
- 编辑、移动日期、复用、删除确认 / 取消和存模板回归通过；删除后没有幽灵展开行，今日合计仍正确重算。
- 可见按钮与无障碍展开状态明确；实际 VoiceOver 未测时如实保持待验，不用层级检查替代朗读验收。
- Core / 全量 App 测试、iOS 构建及相关模拟器实际交互通过，再报告此次三切片完成情况；不自动启动日历或 S3 新业务。

## 验证与交付

每一切片先增加相应回归覆盖，然后执行：

```sh
swift test --package-path Packages/FoodDecisionCore
./scripts/test-ios.sh
./scripts/build-ios.sh
```

原生预览覆盖整页 / 安全区而不只隔离卡片，至少检查浅 / 深色、最大辅助字体、无记录 / 未设目标、已记录与超出状态。模拟器验证真实键盘、sheet、导航与草稿保护，静态测试不能替代手势操作。新增测试数量以实际执行为准，`.build` 中截图 / xcresult / 合成数据库不提交 Git。

每一切片形成独立 `feat/` 提交，按项目授权与 Git 规则推送及非破坏性整合。失败不进入下一切片；不得卸载真机 App 或清库“解决”兼容性。真机操作由用户提供观察或另行实际执行，不能冒称代理验收。
