# OPT09 目标历史实施计划

批准日期：2026-10-10。实施分支：`feat/goal-history`。交付分支：`feat/goal-history-delivery`。基线：`27a2cb8`。原实施提交因邮箱隐私被远端拒绝，保留本地历史，另以公开 noreply 身份建立等价交付提交。

本片让每次目标修改留下独立版本，旧日期使用旧目标，未来目标到指定日期才生效。用户已批准下列规则及实施；现有未提交规划与品牌文档保留在原工作区，不混入本任务。

## 原问题与代码边界

基线中的 `GoalSettingsView.saveGoal()` 沿用现有目标 UUID 和 `effectiveFrom`，调用 `GoalSaveCommand.save()`；命中旧记录后执行 `PersistentGoalProfile.update(from:)`，覆盖营养数值。`TodayView` 从当前目标读取预算，没有按统计日期选择版本。旧数值和变更时间均无法由这条记录还原，将其用于过去日期会把现在的预算套到过去。

本片保留旧目标表，不再从正式设置流程更新它。新写入走 `GoalVersionSaveCommand`，读取走 `GoalHistoryReader` 和 Core 的 `GoalSelectionPolicy.v1`；餐食数值与已有营养快照不重算。

## 已批准规则

- 每次主动确认追加完整目标快照，记录来源、确认时间和生效日期，保留旧版本。
- 默认明天生效，可以明确选择今天整日或未来日期。同一生效日的最后确认版本胜出，不按小时分摊预算。
- 按统计日选择不晚于该日的最大生效日期，再选该日最大提交序号。未来安排不因较早日期的新目标被自动取消。
- 补录餐食按其统计日读取目标。日期跟随手机本地时区，使用 Gregorian 民用日期键；确认时区和对应日界 UTC 保留为审计信息。
- 已覆盖的过去目标不可恢复，显示未知；首片不开放倒填过去目标。
- 来源只说明用户提供的依据，不生成医疗阈值，不声称系统验证医嘱。

## 交付范围

Core 增加不可变目标版本、日期键与版本化选版规则。App 增加追加保存命令、统一读取、来源和生效日期输入、只读版本列表及详情，并连接今日的午夜、前台、时区与保存刷新。

最小版本字段：唯一 UUID、六项目标完整快照（可选项保留 nil / 0）、来源和说明、确认时间、生效民用日期键、确认时区及对应日界时间、递增提交序号、选版规则版本。来源提供“自行设定”和“用户提供参考依据”，后者必须填写说明；说明不作为系统已验证的医学依据。今日目标与餐食统计共用同一个日期窗口的时区。

保留 SwiftUI、Swift 6、SwiftData、现有工程、Bundle ID `com.ning6y6.ShiHeng` 和本地唯一约束。不引入依赖、账号、云同步或后端；不开发日确认、日历、食品搜索、食物卡、照片确认、扫描或 HealthKit。

## 数据保护和迁移

冻结十二实体 V1 不变，新增 `VersionedSchemaV2(2.0.0)` 和独立的第十三个目标版本实体，显式执行 V1 到 V2 迁移。迁移历史表为空，旧目标只用于今日兼容参考；来源与过去生效时间未知。首次明确再确认后才建立可信版本，即使数值相同也要保存第一版。

已识别 V1 的升级先复制受保护的主库 / WAL / SHM 快照，再从快照建立逻辑备份和独立 V1 候选，仅在候选迁移。元数据识别也使用副本，因为系统框架的只读操作仍可能改变原库辅助文件。关闭重开、核对全部旧记录、V2 哈希、空历史表和文件保护后，才原子发布选择。失败保留原库与选择，不清库或卸载。未知结构拒绝，不猜测早期同名版本。所有候选和备份留在私有目录。

新导出采用备份格式 2 / Schema 2.0.0，继续读取格式 1 / Schema 1.0.0。V1 备份恢复到 V2 后历史为空；V2 恢复保留版本、UUID、顺序、nil、确认时间和生效日期。恢复不合并现库，不重确认旧版本。

## 保存和表单保护

保存在独立关闭 autosave 的 MainActor 上下文中执行，先检查输入、当前时间线基线、序号和身份，再一次提交。失败仅回滚私有事务；其他页面草稿不提交、不丢失。

稳定操作 ID 保证同一请求重试只写一次；不同内容不能借唯一约束覆盖。确认时间与日期信息在首次请求固定，修改草稿重新确认。来源和生效日期参与草稿保护；跨午夜或时区后日期已过去时保留输入并要求重新选日，不静默改变选择。
