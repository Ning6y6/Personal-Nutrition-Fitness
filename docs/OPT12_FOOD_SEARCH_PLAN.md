## 3. 本片范围

### 3.1 数据与来源

- 本地正式目录至少 300 个**真实、可选择、通过必需字段校验的独立食品**，含现有 12 项；别名、拼音键及纯测试假食品不计数量。同一食品重复导入不同来源不能充数。
- 优先覆盖按锅称生料所需的肉禽鱼、蛋、蔬菜、豆制品、豆谷、调味料和油，补充熟米饭／面条等常见熟主食。成品菜与英国外卖只做来源抽样，不作为凑齐数量的主体。确切分类数量随候选清单提交核对，不预先伪称已经取得 300 个合格条目。
- 主要来源为 GOV.UK 的 **CoFID 2021 原始 Excel / OGL v3**。本片只读本地随包数据，不调用 CoFID API，不需要 key、账号、后端或联网搜索。
- 中文工作是审核简体名称、同义别名、食品状态和拼音首字母；例如“西红柿／番茄”可以关联同一食品，“生米／熟米饭”不能合并。泛称不能省略肉种、生熟、可食部分等关键差异。
- TFDA 与 SG FoodID 各做基础食材和中式熟食的代表性抽样，提交可复现原始数据、逐项使用权、完整字段与适用条目的核查结论。本方案首批正式目录只分发 CoFID；这两个补源暂不正式导入，纳入清单另待用户审阅批准。抽样缺口不阻塞 CoFID 主方案，任何第三方 API 或采集工具均不在本片引入。
- 新增目录人工排除已明确含猪肉／酒的条目；明胶等来源不明、混合菜配料不清的候选留在待核查清单。通用牛羊鸡肉的营养条目不表示采购产品已获清真认证。既有用户记录不删、不改、不隐藏。

目录要逐条保存原编码、原名、版本、原始基准和审核结果；原始痕量／缺失标记及可取得的视黄醇等扩展字段保存在**版本化公开目录资料**里。本片不往私有健康数据库新增这些字段，也不新增食物维 A 警告、LDL 评分或清真认证规则。

### 3.2 选择器交互

1. 在餐食或模板的某一行点食品，推入当前表单 NavigationStack 的“选择食物”页面；不叠加第二个编辑 sheet。搜索、列表、键盘采用系统控件。
2. 空搜索显示本地可选目录；输入支持简体名、已审核别名、英文原名和拼音首字母。匹配由纯值规则决定，不调用 LLM，不联网补结果。
3. 列表主文案完整显示食品名和生熟等状态，辅助文案显示来源／每 100g；提供轻量资料查看，可看到原名、来源编码、数据版本、营养基准与许可。资料查看不能误选食品。
4. 点选后仅修改发起行的食品引用，返回原表单；保留重量原文、其他分项、标题、日期和焦点处理所需状态。清空选择须是明确动作；返回或清空查询不清空当前食品。
5. 搜索页返回不触发整个餐食表单的放弃；原表单“取消／保存”不会串到搜索页。回到表单后，已有草稿保护继续判断食品变化。搜索页退出不处理外接键盘 Esc 的未确认缺陷。
6. 当前食品不在搜索结果中也不能失去选择；引用删除／无效时显示原有问题并阻止保存，不静默换成第一个结果。
7. 无结果显示清楚的空态和清除搜索入口；本片不加“创建食品”按钮，以免暗中进入 OPT-13。

最近吃过与常用模板是**整餐组合**，保留现有入口和优先复用路径。本片不新增食品级使用次数、最近选择记录或持久化排序，避免扩大为另一项数据功能。

### 3.3 搜索规则草案 `food-search-v1`

- 对查询和搜索键做统一的宽窄字符规范、去首尾空白及使用固定 `en_US_POSIX` locale 的大小写归一；连续空白分成词，各词均需命中。普通字符按字面匹配，不当正则表达式；验收切换英国、中国及土耳其地区时，同一查询得到相同结果。
- 排序先完整名称／别名精确匹配，其次前缀、包含，拼音首字母匹配放后；同级按冻结目录排序及 UUID 打破平局。相同输入与目录版本结果必须相同。
- 拼音键只从审核后的中文名／别名生成并随目录冻结，多音字写明确例外；“鸡胸肉／jxr”等接受用例必须对应真实批准条目。英文名搜索是辅助能力，不代表完整英文 UI。
- 不做模糊纠错、营养推荐、医疗排序或无证据的简繁别名扩展。同名不同食品保留为不同 UUID 并显示区别。
- 将 SwiftData 实体映射为 Sendable 的不可变值供 Core 匹配，不跨 actor 传模型对象，不用无法落入数据库谓词的计算属性做 SwiftData predicate。本片 300 项的本地过滤不与 OPT-11 餐食分页混合。

## 4. 数据结构、初始化与兼容

### 4.1 推荐设计：目录资料版本化，数据库结构不动

建议公开目录包含三个可追溯部分：来源登记表、审核后的食品／别名清单、原始营养与转换证据。每次发布记录目录版本、规则版本及文件 SHA-256；路径与具体格式在实施时沿用工程资源管理方式，不增加第三方运行时依赖。

FoodItem 仍存现有字段；本片新增食品的 `source` 文字包含来源、数据版本、原编码和每 100g 基准。中文别名、拼音、原始扩展字段、许可在随包公开资料中按稳定键查询，不塞进持久化 `source` 作为难以校验的 JSON。

旧 12 项用显式兼容映射保留 UUID。映射到公开资料前核对 UUID、名称、单位、来源及营养指纹，不能只因 UUID 相同就认定旧记录仍为原食品。自建／恢复后无法可靠匹配的食品继续按本地值可用，资料显示无法核实；不套用他人的别名或来源证据。

**V1 十二实体、V2 十三实体、唯一约束和现有备份版本均不变；本片不新增 Schema 版本或迁移步骤，已有 V1→V2 迁移链继续保留。** 新目录版本不等于数据库 Schema V3。以后若需要把扩展营养、食品版本或证据持久化到个人记录，先另提 V3、旧库迁移及备份恢复方案，不借本片加字段。

### 4.2 受控追加与失败处理

- 完整验证随包清单及稳定 ID 后，在关闭 autosave 的专用上下文执行新增目录的追加命令；不借父表单共享上下文保存，以免顺带提交未完成的餐食／模板。
- 只插入缺失的 ID，不覆盖同 ID 本地内容；同 ID 不同内容报告目录冲突并保留本地记录，不能使用 upsert 覆写。既有废弃种子行为单独保留，本片的新追加命令不扩充删除名单。
- 单次新增集合原子保存；失败回滚新上下文，保留原目录和父表单，显示可重试状态。失败后不假称已达 300 条；重试读取真实存储结果，不重复插入。
- 成功初始化后，打字、筛选、查看资料和取消选择零业务写入。连续进入、重复点选、App 重开及备份恢复后再次初始化均幂等；唯一约束保留，并验证重复触发／冲突处理。
- 使用当前容器和恢复选择机制，不复制用户私库进工程。恢复旧备份后允许重新追加缺失的公共目录；恢复出的已有记录、餐食快照、模板用量和目标版本不得被替换。
- 导入目录不能更新历史餐食快照，也不能在启动时重新计算既有餐食；本片不修 OPT-14 的元信息编辑边界。

## 6. 自动验收清单

下面是已批准的验收要求；制定计划时未运行，2026-10-18 实际结果另见交付报告。只使用公开食品与新建合成文件库；不写真实设备记录，不把私库、健康导出或截图加入 Git。

### 6.1 Core 与资料校验

- 完整运行 `swift test --package-path Packages/FoodDecisionCore`。
- 中文名、别名、英文名、拼音首字母、空白／宽字符／大小写、多词 AND、无结果、确定排序、同名不同 ID 与重复 ID 拒绝有明确样例。
- 生米和熟米饭不混并，食品状态始终可区分；搜索不改变营养或选择草稿。
- 导入规则的数值 0／Tr／N／空白分离，AOAC 不被 NSP 顶替，100g／100ml／每份和每 100g 脂肪酸不串基准；kJ 不当 kcal，钠 mg 正确换成盐 g，不重复换算。
- 保留来源能量／碳水口径，RET 与 RE／RAE 不混并，反式脂肪不重复累加。缺必需字段的候选不能成为可选择食品，纤维未知保持 nil。
- 目录所有正式条目均可构造现有 Core FoodItem；ID 唯一、字段有限非负、审核与来源齐全；至少 300 是真实食品数量，另报来源／分类／状态分布及隔离数量。
- 对原始字段到发布值做逐项机器核对，再人工核对每个正式条目的中文名、状态、原码、单位与字段映射；最终报告保留抽查证据和审查局限，不能拿生成成功代替数值核查。

### 6.2 全部 App 单元与 SwiftData 文件库

- 使用 `./scripts/test-ios.sh` 运行共享 Scheme 中**全部 `FoodDecisionAssistantTests`**，不能只跑新增测试后声称全量通过；脚本已支持 `SHIHENG_SIMULATOR_DESTINATION` 和透传 xcodebuild 参数，使用 `-only-testing:FoodDecisionAssistantTests` 指定整个单元 target；不能漏掉文件库测试。
- 新建文件库：原有 12 项与合成自建食品初始化后执行追加，关闭重开、第二次追加、模拟中断／重复触发后 ID 与内容稳定。
- 注入保存失败及真正禁止写入的测试文件库：新增记录不半写，不提交父表单未保存的数据；保留错误与重试；恢复写入条件后重试成功。
- 同 UUID 不同内容不覆盖；未知来源食品仍可按本地值选择，不能错误附上公共别名。缺失引用、选择返回途中删行、选后食品失效均不串行或静默保存部分餐食。
- 对既有 12 项、用户合成食品、餐食／分项／快照／顺序、模板／使用次数、目标版本及本地唯一约束做前后比对。搜索与取消的只读基线建立在目录初始化之后。
- 现有备份导出→独立新库恢复→关闭重开：原始字段、nil、UUID 与关系一致；旧备份重补目录幂等，历史记录未重算。V1／V2 及备份格式冻结检查通过。

### 6.3 相关模拟器实际交互

## 7. 用户验收的准确流程

实施交付后提供包含真实目录关键词的截图和逐步清单，以下为预定流程。真机沿用已有 App 覆盖安装，不卸载、不清库；只读检查优先，需要保存计时餐时由用户自愿使用当次真实餐，或在专用 QA 环境保存合成餐。

1. **找到并区分食品**：从“今日→记录一餐→空白记餐”进入选择器，分别搜索目录已核准的“番茄／西红柿”和“鸡胸肉／jxr”，确认别名回到相同原码、状态清楚；再搜“米”，区分生米与熟米饭。只返回不保存，今日餐数和总量不变。
2. **保护原输入**：已有两行，第一行重量输入 `100.0`，第二行输入 `.`；从第二行搜索、查看资料再返回，两行与原文原样保留。选择只改变第二行；非法重量仍不能保存。明确放弃后无新增餐食。
3. **完成正常记餐**：为本次真实餐选食品、填克重、保存，返回今日；展开及详情的食品、重量和营养一致。再次打开编辑，只进入搜索后返回再取消，不应额外新增或丢弃历史分项。
4. **检查其他入口**：从常用模板复用，再从模板编辑进入选择页；取消不改变模板或使用次数。真正保存一餐时才沿用已有的模板使用计数行为。
5. **可访问性**：浅／深色、最大辅助字号下重复搜索与返回；开启真实 VoiceOver 听到名称、状态、当前选择与可执行操作，完成一次选择／取消。截图或合成 AX 树不能替代此项朗读操作。
6. **五次模板复用计时**：使用相同已准备好的常用模板，每次从点今日“记录一餐”开始，到保存成功返回今日且条目／汇总刷新结束；含正常确认食品、修改本次重量和保存的动作。预先固定连续五轮：各轮的取消、纠错和重试均计入该轮从入口到最终成功的总耗时；任一轮未完成则本项未通过，不能删除该轮后补一个成功样本。五轮全部完成后中位数须 ≤30 秒，五个原始耗时与失败过程全部保留。XCTest 用例耗时不能替代人工计时；VO／最大字号单列观察，不拿自动重试把失败样本磨掉。
7. **来源与离线**：断网后可继续搜索；设置“数据来源与许可”可看到来源、版本、署名、许可链接和修改说明。未核实的认证或缺失营养不显示为确定结论。

真机、VoiceOver或五次计时未做时，报告为“自动门禁通过，相关人工验收待完成”，不能宣布 OPT-12 全部验收通过。完成验收后先报告结果与下一建议切片，再等用户批准；不自动开始食物卡、菜谱批次或日确认。
