# OPT-14A：历史餐食快照保护

日期：2026-10-20。基线：`c12076d`。交付分支：`fix/opt14a-snapshot-protection-delivery`。

用户批准修订后的 OPT-14A。本片只修旧餐编辑边界，个人食物卡 OPT-13 仍待后续批准。

## 已实施规则

- 只改餐名／时间，只更新相应字段，保留原分项 ID、名称、克重、营养、次序、整餐总量、证据等级和其他未改字段。当前食品更新或缺失不影响这一操作。
- 同一食品改克重，按“本次打开时的原营养快照 × 新克重／原克重”计算，不查询当前食品，不弹选源框；恢复原克重直接使用原快照。保存重试和连续预览不累乘。
- 新增或明确换成另一食品，才使用保存时当前有效食品的数据；其余分项不重新计算。只更新／删除目标分项，保留未改分项身份；新增造成排序碰撞时统一编排新次序。
- 原名称和营养依据显示为历史快照；预览与保存使用同一策略。原未知纤维仍未知，已知 0 仍为 0；不使用显示取整值进行计算，拒绝非法量、非有限数、溢出及正值异常归零的下溢。
- 旧异常信息可通过纯元信息更新原样保留，不顺手修复或纳入正式汇总。D／未知等级不能靠本片改记录方式变正式；合法估算只改名称、时间、克重仍保持原等级。
- 保存使用独立 context 的显式事务，未提交阶段失败仅回滚该事务，原记录及表单原文保持；提交成功后逐分项、再父记录做定向只读刷新，不提交或回滚共享草稿。已提交但刷新失败会明确提示并允许仅刷新重试，同一目标不重复缩放。编辑基线与草稿一样由 State 固定，父视图重建不会重捕获基线。

保留原生餐食／模板布局、分项编辑模式、取消保护和删除确认框定位。新餐与模板计次路径保持。本片没有 V3、迁库、备份格式升级、修订表、容量支持、新依赖或个人卡入口。Bundle ID 保持 `com.ning6y6.ShiHeng`。

## 真机验收步骤

覆盖安装本片新版，不卸载、不清库。只使用自己明确新建的测试餐；未知真实记录先只读检查。建议取内置“熟长粒白米饭（无盐）”100 g，当前值应为 131 kcal；若用户本地该食品已不同，则记下实际原值，后续检查按比例而非强套 131。

1. **准备与基线：**新建名称唯一的“OPT14A 验收餐”，选择上述米饭 100 g 保存。打开详情，记录热量、营养、食品名称、证据等级及时间。可另加一种食物作为“不应变化”的对照分项，分别记下各自重量。
2. **只改餐名／时间：**编辑测试餐，只改名称保存；再单独修改时间保存。原分项名称、克重、营养和证据等级必须不变。若移动到另一日期，仅摄入所属日期和相应日合计变化，餐食本身营养不变。
3. **原比例改量：**编辑仅米饭 100 g 的测试餐，改成 200 g。预览应由 131 变 262 kcal，不出现选择来源弹窗；保存后详情也是 200 g／262 kcal，证据等级不变。重开 App 再检查。
4. **同会话往返：**重新打开编辑，在同一会话里依次改成 100、200、100 g。预览分别为 131、262、131 kcal；保存后保持最终值。若有其他分项，它的名称、重量与营养保持，仅整餐合计随目标分项变化。
5. **继续编辑／放弃：**输入 200 g→取消→继续编辑，仍保留 200 g 和对应预览；再次取消→放弃，详情仍为原先已保存值。重新打开不应留下未保存重量。已有餐食删分项后的取消保护仍需生效。
6. **换食物／新增／移除：**只在测试餐新增或换一条食品，预览按所选当前食品计算；其余原行不变。多行中删除一行，留下行名称／重量和合计正确。添加空白行仍不能保存，删除空白行后可保存。原生“编辑／完成”与删除确认框位置保持。
7. **模板回归：**打开自建模板，编辑／取消／继续／放弃仍保留原保护；模板带入的新餐仍按当前食品计算，不把历史餐快照当成当前模板来源。无需修改真实常用模板来做破坏性试验。
8. **外观与重开：**浅深色及大字号检查名称、重量、保存、键盘完成和错误提示；重启后测试餐结果保持。VoiceOver 若实际检查，单独记录名称、单位及提示是否正确，不用模拟器代替。

源食品已更新／删除、异常旧值、精确分项 ID、保存失败／重试、备份恢复等无法从本片正常真机 UI 完整制造的场景，由合成命令／文件库测试验证，不为验收新增生产入口，也不手改真机库。当前还没有个人食物卡编辑页，这是下一片范围。

任一出现即不通过：改餐名导致营养变化；同食品改量查当前库重算；原估算等级被自动升级；未知变 0；无效行被静默丢弃；取消或未提交阶段失败改变已保存记录；重试重复缩放；原布局或已验收取消规则退化。已提交但回执／刷新失败时，提示须如实说明保存状态，不能承诺“没有保存”；重试须核对目标而非再缩放。
