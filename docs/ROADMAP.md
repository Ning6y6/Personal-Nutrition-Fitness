## P0：让“记录一餐”可以长期使用

目标：先降低日常录入成本，再接入 AI。

1. [x] 支持查看、编辑和删除历史餐食；删除和修改后今日汇总立即重算。
2. [x] 增加“最近吃过”和个人常用菜模板，支持一键复用后只修改重量。
3. 增加自定义食物和个人菜谱批次，解决中餐家常菜需要重复添加多个分项的问题。
4. 增加外卖/堂食手动估算入口，允许使用份数、碗数、盘面比例和多人分食比例。
5. 完成真机触控验收：键盘、动态字体、深色模式、VoiceOver 和快速连续录入。

完成标准：连续7天中至少5天完成全部餐食记录并作日级确认；重复录入常用餐≤30秒。日级确认依赖S3，记录率与证据等级分别报告；当前尚未完成该实机验收。

## P1：计划 A 的拍照估算确认流程

目标：覆盖无法称重的餐厅、食堂、外卖和聚餐。

1. 建立相机/相册入口；上传前移除 EXIF 和 GPS，只在本地保存受控引用或哈希。
2. 先连接现有 `FixtureMealVisionProvider`，完成草稿、加载、失败、超时和低置信度界面。
3. 展示每个菜品/食材的低、中、高克数、置信度、烹饪方式和隐藏油/酱汁。
4. 支持小/中/大份、盘面比例、“两人份吃一半”和直接修改克数。
5. 用户确认后才生成证据 C 记录；未确认草稿保持证据 D，不进入正式营养汇总。
6. 用 3—5 份“先拍照、后称重”餐食验证流程，再扩展到 20 份精度测试。
7. 本地确认闭环稳定后再选择真实视觉模型和 API，不在仓库保存 API Key。

完成标准：估算餐可以被用户完整修正；隐藏油不会丢失；营养范围由本地食物数据计算并可追溯。

## P2：食品标签扫描与个人约束判断

目标：在英国超市货架前给出简短、可解释的购买判断。

1. 到本切片开始时安装并审查 `vision-framework` skill。
2. 使用 Vision/VisionKit 识别配料表、营养表和条码；允许先保存“未核对”临时结果。
3. 先检查明确违规证据，再检查字段完整度，然后输出清真标记和营养评分。
4. 补剂使用独立结论：不符合约束、需咨询药师、未发现冲突。
5. 在原图上标出触发规则的文字证据；颜色、图标和文字同时表达结论。
6. 缓存 Open Food Facts 查询并设置合规 User-Agent，不依赖在线搜索完成硬约束判断。

完成标准：关键字段识别率可以量化；任何绿灯结论都需要已核对数据；LLM/OCR 不能绕过本地硬规则。

## P3：HealthKit 与活动联动

目标：读取真实活动数据，但不简单把手表热量全部“吃回来”。

1. 到本切片开始时安装并审查 `healthkit` skill。
2. 读取步数、活动能量和训练；写入热量、蛋白质、碳水、脂肪、饱和脂肪和纤维。
3. 验证保存、更新、删除和回查，避免编辑餐食后在 HealthKit 产生重复样本。
4. 训练日与非训练日使用可解释的目标调整策略；Apple Watch 热量仅作为趋势信号。

完成标准：真机授权与同步稳定；同一餐反复编辑不会重复写入；同步失败不影响本地记录。

仍按原排期等待后续批准；没有随 UI-1 / B-1 提前实现。
