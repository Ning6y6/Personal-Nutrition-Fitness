## 授权、观察与实现

用户再次报告真机“完成”偶发消失、相同步骤重试又正常，并要求设置页全部入口统一为正文色加右箭头。本片承接该反馈；不因此前模拟器通过就关闭真机问题。

设置页原有三个 Button 打开 sheet，继承绿色强调色；两个 NavigationLink 使用正文色及系统箭头，因此出现不一致。新增 SettingsEntryLabel 只共享标签外观：五项标题 Color.primary（深色白／浅色黑），图标保持 DesignTokens.accent。三个 Button 添加装饰箭头并用 plain 样式；两个 NavigationLink 沿用系统箭头，不重复添加。截图核查后，将装饰箭头从 secondary 改为 tertiary，以匹配原生箭头的灰度。原分组、说明、三个 sheet、两条 push 路由和原有 ID 保持，另补 goalSettings／backup 标识符。最小点击区 44 pt，允许大字号自然换行，整行文字及空白可点，装饰图标不重复朗读。

键盘核查没有证明 App 主线程卡顿。现有 WeightTextField 是纯 SwiftUI，稳定 UUID 绑定焦点，未发现 UIKit 焦点桥接。餐食／模板的 keyboard toolbar 原来随导航根部条件撤销和重新注册；仅将其移出条件又可能把父完成按钮带入搜索页。此次将四个表单统一采用个人卡已验证的显示方式，减少对该注册链路的依赖：

- FormKeyboardCompletion 根据当前表单焦点渲染自然高度的 safeAreaInset 完成区，使用原生 glass／large，没有整条背景、固定行高、通知、延时或强制重建视图。
- 餐食／模板同时要求 navigationPath 为空；进入搜索／资料页前原有清焦点动作保持，父完成不进入搜索键盘。
- 目标和个人卡依自身焦点显示。四个原 keyboardDone ID 和设焦点为 nil 的动作保持；取消、保存、光标、输入原文、分项 ID 和历史快照逻辑不改。

这是有明确代码边界的稳定性调整，不等于已定位用户偶发问题，也不能声称已根治。真机若仍出现，应根据当时页面、输入法、前几步操作及其他控件是否响应继续取证。
