用户已确认上一片目标表单真机验收通过，并批准本片。前片反馈属于用户验收；本片仍独立验证。只修复今日页展开后的编辑、复用、查看详情被底部入口遮挡，不并入日期、热量小数、紧凑记录按钮或评估中的其他建议。

## 缺陷与修复

用户及`docs/APP_REVIEW_2026-10-11.md`描述的原场景是：`6a0b270`、iPhone 18 Pro Max / iOS 27，今日仅一条米饭180g；点开餐食后，明细末尾操作行落在记录入口和Tab后面。该评估未在`f3cfd5e`复测，不能把它当作本轮代理测试结果。

本轮修复前实际截图显示下方历史入口与固定记录入口重叠；边界测试测得滚动视口底部956pt、记录按钮顶部783pt。旧`.safeAreaInset`留出滚动空间，但可见滚动区域仍延伸到入口后方。此边界证据不等于已经证明历史入口永久不可达。

1. 用自然高度的兄弟布局分开滚动区和底部操作区，不硬编码Tab高度，不忽略安全区。全宽记录按钮、系统Tab和原点击行为保留。
2. 今日专用操作行放到餐食摘要下，长食物及营养明细放在它下面。共享组件默认仍用历史页的原顺序；编辑、复用资格、详情及数据快照不变，只渲染一套按钮。
3. 自动定位的布局就绪信号来自新插入的操作组，目标不依赖整份长明细的高度。常规字号显示摘要和三个操作，不强制摘要额外移到上半屏；辅助字号优先把完整操作组放入视口。长标题或明细允许正常滚动阅读。
4. 不增加固定延时或等待全部展开动画。沿用系统动画、减少动态效果及匹配请求的一次消费；手动拖动、换餐、日期、Tab、前后台和打开表单的失效规则保留。

不改Core、SwiftData V1/V2、迁移、保存命令、备份、本地唯一约束或`com.ning6y6.ShiHeng`，不新增依赖。原7个修改文档、扫描计划和用户新增评估全部保留，不混入修复。

## 独立验收

- Core全量、全部App单元测试及`./scripts/build-ios.sh`。
- 真实合成QA场景：今日恰好一条米饭180g，点击展开后不再使用滚动助手；三个操作均完整在记录按钮上方、可点击且至少44pt。实际进入编辑、复用、详情，取消返回后原餐保留。
- 检查滚动视口、入口、Tab完整边界；滚到底实际点历史入口，返回后点记录入口、切Tab再返回。
- 常规大屏、小屏及小屏真实最大辅助字号；再验证收起、重开和换餐的每一次展开。最大字号的长摘要超过阅读区时，展开前点击其真实可见且可命中的部分，不要求整块摘要同屏；展开后仍严格要求三个操作全部完整可见。三个操作通过断言后，才允许定位摘要进行收起或滚动打开的表单核对重量，不能以手动滚动帮助操作行验收。
