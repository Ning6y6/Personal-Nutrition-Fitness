## 失败证据与未闭合事项

- 修复前R0实际边界失败：滚动视口底部956pt，大于记录入口顶部783pt。它证明视口延伸到入口后方，不证明历史入口永久不可达。用户及评估的原复现是`6a0b270`的一条米饭180g，本轮代码基线为`f3cfd5e`。
- R2、R3曾要求摘要额外位于阅读区上半屏，实际录像／PNG显示操作完整可见、摘要在下半区。移除这项超出遮挡目标的偏好，完整边界、真实点击及稳定观察保留。
- R4在44pt精确比较处失败。R5原始附件测得`43.999999999999943`；测试增加0.001pt浮点容差，生产按钮仍为44pt，远小于一个像素的差异不构成实际缩小。R5收起重开换餐通过。
- R7的餐食准备失败于AX名称框空白处的长按，R8失败于要求超高摘要整块同屏，R10单餐失败于尚未实例化的编辑重量字段。这些是具体测试交互／前置假设失败，未归为环境问题。依据实际截图改用文字边缘的原生选择、可见摘要部分和打开表单后的真实滚动；唯一菜单动作、全文输入、唯一重量字段及展开后三个完整操作断言均保留。R12完整往返通过，未修改生产表单或注入数据。

## 真机验收流程

只使用本人已有的真实餐食，不为测试登记虚构米饭，不保存编辑／复用草稿，不删除已有餐食。180g单餐原场景已由合成QA承担。

1. 在设置→本地备份私下导出全量备份。原地更新同一Bundle ID的App，保留数据；记下原系统字号，选择今日已有的有效餐食，私下记下重量和今日汇总。
2. 常规字号下，将摘要滚到靠近阅读区下方后点一次展开。此后不滑动，检查编辑、复用、查看详情三个按钮全部在记录入口上方，没有文字或按钮边缘落到入口／Tab后面。通过标准是三个都完整可见，而非仅露出一条边。
3. 直接点编辑、复用，只核对预填重量后取消；详情核对原重量后关闭。每次返回检查三个操作仍完整可见、原餐与今日汇总不变、没有新增记录。表单本身需要滚动时可以正常滚动。
4. 收起再展开；有第二条今日真实餐食时切换展开它，每次先检查三个操作，无需额外滑动使操作出现。没有第二条就将换餐记为未测，不补假记录。
5. 设置系统最大辅助字号，重复展开和三个操作实际点击。长摘要允许先滚动找到可见部分并点击；展开后检查操作时不滚动。三个操作确认后可滚动定位摘要进行收起。结束恢复原字号；无小屏真机时不把模拟器结果写成真机小屏通过。
6. 滚到今日底部，打开查看全部历史并返回；点记录一餐再取消；切设置后返回今日。检查入口与Tab边界、原餐和汇总。逐项记录通过／失败／未测；失败私下保留机型、iOS、字号和截图，个人资料不进Git。
