## 实际交互边界与待测项

只在 `ShiHeng-Kcal-QA`（iPhone 18 Pro Max／iOS 27）运行；真实 App 窗口为 440×956 点。每轮通过正常表单创建唯一名称的公开米饭 100g，先核对真实目标圆环及四项营养标题存在并留截图，再将收起的餐食定位到阅读区底部后点击展开。展开之后、三操作断言通过之前没有测试驱动滚动；三项都须完整位于真实阅读区、可命中、至少 44 点并连续稳定。通过后打开详情核对食物／100g，仅删除本轮自己的合成餐，不设置或改写目标。

常规字号实际阅读区 y≈116…767，三项操作 y≈702.33…746.33，均高 44 点。AX5 阅读区 y≈116…747.67，三项操作分别 y≈552…610.67、618.67…681、689…747.67，均完整可见。截图和原始边界分别位于两个成功结果的 `*-attachments/`。这是两次单次展开与详情回读的相关 UI 成功执行，未执行全部 UI 套件、本片未重跑收起重开／换餐或编辑／复用完整功能往返。

375／430 点是独立卡片合成宽度；本轮实际交互只在上述 440 点模拟器完成，不将其说成小屏真机。最大字号和外观修改结束后已经恢复原值并读回；没有变更键盘偏好。

本轮日志仍记录既有 `Invalid frame dimension` 和原生预览 appearance-transition 警告，不以本片通过认定这些已修复；既有键盘布局问题也未定位关闭。App 单元日志两处 Code 513 保存失败来自明确的只读文件库故障注入用例，该两个保护用例均通过，不是本轮环境权限门禁失败。Core、App、UI 与构建均成功执行，没有遗留环境阻断。真机、VoiceOver 和外接键盘未在本片验证。

## 真机验收方法

1. 使用已有目标和餐食打开“今日”，核对每项标题、数值、进度、说明归属清楚，营养项之间留白一致，数值与本片前一致。
2. 切换浅／深色及较大文字，滚动检查换行后没有遮盖、截断；纤维未知仍显示未知或已知小计，不显示虚假的零或缺口。无需为此修改真实目标或补造餐食。
3. 点开已有餐食，确认编辑／复用／查看详情完整出现在“记录一餐”上方；收起重开、切换餐食后再检查。不需要为验收保存或删除真实记录。

模拟器渲染和交互不能替代这项真机体验验收。Esc 外接键盘仍是[未确认问题](ESC_KEYBOARD_REVIEW.md)。
